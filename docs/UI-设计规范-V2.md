# 界面设计规范 V2

> 适用于「灵感与待办」。本文件只定义**视觉与交互清晰度**，
> 不改变产品方向：四个一级入口、一种 `Record` 数据、首页是时间线、完成≠删除、
> 不新增任何功能。

---

## 一、设计目标

产品只解决两件事：**突然想到一个东西 → 立即记下来**；**突然想到一件要做的事 → 立即记下来并完成**。
核心体验是「想到 → 写下 → 继续做自己的事情」。

因此界面的第一职责是：**让「在哪里写」和「写了什么」永远一眼可见。**
美观是第二位的，服务于可读性，不是独立的装饰目标。

判断任何改动的标准：**它有没有让「想到 → 写下」更快？**

## 二、当前界面存在的问题（设计审计）

| # | 问题 | 证据 |
| --- | --- | --- |
| 1 | **对比度不合格** | `--color-ink-faint: #a8adb3` 在白底上仅 **2.2:1**（AA 要求正文 4.5:1、大字 3:1），却用在时间戳、日期分组、空态文案、日历星期、占位符、已完成内容上 |
| 2 | **字号阶梯失控** | `11.5 / 12.5 / 13 / 13.5 / 14 / 14.5 / 15 / 16 / 16.5` 共九级，相邻仅差 0.5px，人眼无法分辨，等于没有层级 |
| 3 | **灵感与待办无法扫视区分** | 两者只有一个小图标不同，但行为完全不同（一个只是记下，一个要去做） |
| 4 | **Toast 遮挡详情操作** | 提示条定位 `bottom-[calc(72px+safe-area)]`，正好压在底部抽屉的按钮上 |
| 5 | **空态没有指引** | 「你记下的每一条灵感与待办，都会按写下的时间留在这里」是文学描述，新手读完仍不知道下一步做什么 |

## 三、设计令牌

### 3.1 色彩

| 令牌 | 值 | 用途 | 对比度 |
| --- | --- | --- | --- |
| `canvas` | `#FAF9F7` | 页面底色（暖纸感） | — |
| `surface` | `#FFFFFF` | 卡片、面板 | — |
| `sunken` | `#F4F2EF` | 输入区底、侧栏底 | — |
| `ink` | `#1F2328` | 正文、标题 | 15.2 : 1 |
| `ink-soft` | `#5A6169` | 次要文字、**时间戳**、元信息 | 6.1 : 1 |
| `ink-faint` | `#8B9199` | 装饰性辅助（**不得承载关键信息**） | 3.1 : 1 |
| `line` | `#E9E6E1` | 分隔线、边框 | — |
| `idea` | `#B8843F` | 灵感主色（赭石） | 4.6 : 1 |
| `idea-soft` | `#F7F1E8` | 灵感浅底 | — |
| `todo` | `#4F7391` | 待办主色（雾蓝） | 5.2 : 1 |
| `todo-soft` | `#EAF0F5` | 待办浅底 | — |
| `danger` | `#B4544B` | 删除等破坏性操作 | 5.4 : 1 |

**为什么用双语义色**：灵感是发散、待办是行动，两者的行为不同。
赭石（暖）与雾蓝（冷）都是低饱和色，在暖纸底上互不打架，
但扫视时一眼能分出类型。这是「易用」层面的改进，不是装饰。

**硬规则**：任何承载信息的文字，对比度不得低于 4.5:1。
`ink-faint` 只允许用于分隔线旁的小圆点、装饰性描边等不承载语义的位置。

### 3.2 字号阶梯（七级，相邻至少差 2px）

| 级别 | 字号 | 字重 | 用途 |
| --- | --- | --- | --- |
| display | 28 | 500 | 日期大标题（首页） |
| title | 20 | 500 | 页面标题（灵感 / 日历 / 待办） |
| lead | 17 | 400 | 详情正文 |
| body | 15 | 400 | 列表内容（最常用） |
| note | 13 | 400 | 说明、元信息 |
| caption | 12 | 400 | 时间戳、日期分组、数量 |
| micro | 11 | 400 | 日历星期、角标 |

字重只用 400 与 500 两档。**禁止出现 600 / 700。**

### 3.3 形状与间距

- 圆角三档：`8px`（行、小按钮）/ `12px`（输入框）/ `16px`（卡片、面板）
- 间距基准 `4px`；卡片内边距 `12–16px`；区块之间 `20–24px`
- 阴影只允许两处：**输入卡片**（`0 1px 2px rgba(31,35,40,.04)`）、
  **浮层**（抽屉 / 弹窗 / Toast）。列表行一律无阴影，靠分隔线。
- 所有可点击目标触摸区域 ≥ `44×44px`

### 3.4 动效

- 打勾完成：勾选框 `200ms` 填充动画，随后该行 `420ms` 淡出上移
- 抽屉 / 弹窗：`220ms` 上滑 + 淡入
- Toast：`200ms` 淡入
- 全部动效在 `prefers-reduced-motion: reduce` 下降为 0.01ms

## 四、视觉语言：形状即类型

这是本方案的核心识别点。

| 类型 | 节点形状 | 颜色 |
| --- | --- | --- |
| 灵感 | **实心圆** | 赭石 `#B8843F` |
| 待办（未完成） | **空心圆角方** | 雾蓝 `#4F7391` 描边 |
| 待办（已完成） | **实心圆角方 + 白勾** | 雾蓝填充，内容加删除线并降为 `ink-faint` |

圆形 = 发散的想法，方形 = 待勾选的行动。**不读文字也能扫出哪条是什么。**
导航图标沿用同一套语言，保持认知一致。

## 五、逐界面设计

### 5.1 首页 · 时间线

```
┌──────────────────────────────┐
│  ● 仅本机            [搜索][设置] │
│                              │
│  9月30日                      │  ← display 28
│  星期三                       │  ← caption 12
│                              │
│  ┌────────────────────────┐  │
│  │ 想到什么，先写下来        │  │  ← 输入卡片（16px 圆角 + 阴影）
│  │                        │  │
│  │ [● 记为灵感] [▪ 记为待办] │  │
│  └────────────────────────┘  │
│                              │
│  今天 · 4 条 ───────────────  │
│  │                           │
│  ●  灵感与待办应该只解决两件事   │  ← 实心圆 = 灵感
│  │  03:07                    │
│  │                           │
│  ▪  给 STM32 那块板子加个 CAN  │  ← 实心方+勾 = 已完成
│  │  03:07 · 已完成             │
│  │                           │
│  ●  可以试试把日志按天分文件     │
│  │  03:07                    │
│  │                           │
│  ▫  周末把智能车驱动板焊完      │  ← 空心方 = 待办
│     03:07                    │
└──────────────────────────────┘
```

要点：

1. 输入区是**整个 APP 唯一的写入入口**，必须是页面上视觉权重最高的元素：
   白底、16px 圆角、带阴影、占位文字用可读灰度。
2. 按钮文案从「灵感 / 待办」改为 **「记为灵感 / 记为待办」**，
   直接说明点击后果，消除「不知道点了会发生什么」。
3. 未输入内容时按钮**不降低透明度**（那会让按钮消失），
   而是换成中性灰描边；输入后变为各自的语义色。**形状恒定，只换颜色。**
4. 桌面端自动聚焦输入框（`pointer: fine`）；手机端不自动聚焦，避免弹出键盘遮挡。
5. 时间线左侧是一条 `1px` 的极细竖轴，节点承载类型信息。
6. 日期分组头为「今天 / 昨天 / 9月28日」+ 条数，右侧接一条渐隐分隔线。

### 5.2 灵感页

- 标题「灵感」+ 副标题「记下了 N 个想法」
- 按天分组，行结构与首页一致（但无竖轴，因为类型唯一，轴无信息量）
- 空态改为可执行指引：「还没有灵感。在首页输入框写下第一个想法吧。」

### 5.3 待办页

- 标题「待办」+ 副标题「还有 N 件没做」
- **换成行动清单的语言**：左侧 `19px` 大勾选框、行间 `0.5px` 细分隔线、去掉时间线
- 这里不需要回答「什么时候记的」，只需要回答「还有什么没做」
- 完成后该行 `420ms` 淡出并离开列表，同时弹出「已完成 / 撤销」
- 列表底部有默认折叠的**「已完成」区**，见 5.7

### 5.7 已完成区（撤销误打勾）

打勾这个动作太轻了 —— 手滑一下那条就从列表里没了，而弹窗提示只有几秒。
**只有几秒的撤销入口等于没有**，用户意识到点错的时候它已经消失了。
所以待办页底部有一块常驻的「已完成」区：

- 折叠态：`▸ 已完成 · N 条`，一行，样式与日期分组头一致，不干扰主列表
- 展开态：每条显示划线内容 + **「今天 14:32 完成」** + 一个写明「撤销」的按钮
- 时间必须带「完成」二字 —— 否则会被误读成创建时间
- 撤销按钮是**带文字的按钮**，不是图标：用户就是没看见上一次的撤销机会，
  这次不能再靠一个符号去暗示
- 撤销按钮触摸目标 ≈ `44px`（行高 `56px` 减去上下 `6px`）

**这块区不是归档，是后悔药。** 所以：
- 不做分组、不做时间窗、不分页 —— 归档归首页时间线和日历管
- 不做勾选框（勾选框在这里只会让人以为是「再勾一次」）
- 行用 `data-testid="completed-row"`，与主列表的 `record-row` 分开，
  这样「打勾后从待办列表消失」的既有约定仍然成立

同时把带撤销按钮的 Toast 默认停留时间从 `5s` 提到 **`8s`**（`TOAST_UNDO_MS`），
纯确认类提示用 `TOAST_NOTICE_MS = 2500ms`。

### 5.8 导航顺序

`首页 · 灵感 · 待办 · 日历`。

灵感与待办是「记东西 / 做事情」这一对，挨在一起；日历是「回看某一天」的检索入口，
排最后。桌面侧栏竖排时日历就在最下面，手机底部导航横排时日历在最右边，两边一致。

### 5.4 日历页

- 月份标题「2026年9月」+ 左右翻月
- 日期格：数字 + 有记录的日子下方一个 `4px` 赭石圆点
- **今天**：数字用赭石色；**选中**：`26px` 赭石实心圆 + 白字
- 下方列出该日全部记录，标题「9月30日 星期三 · 2 条」
- 日历回答的是「我在哪一天记下了什么」，**不是**「某一天要做什么」

### 5.5 详情

- 手机：底部抽屉；桌面：右侧面板（见 5.6）
- 内容用 `lead 17px`
- 元信息表：创建于 / 最后编辑（有则显示）/ 完成于（有则显示）
- 操作：编辑、删除、（已完成则）恢复为待办
- **删除永远是可撤销的软删除**，弹出「已删除 / 撤销」

### 5.6 桌面端

```
┌──────────┬────────────────────────────┬──────────────┐
│ 灵感与待办 │  9月30日 星期三              │  灵感         │
│          │                            │              │
│ ▸ 首页    │  ┌──────────────────────┐  │  灵感与待办…   │
│   灵感 12 │  │ 想到什么，先写下来      │  │              │
│   待办  4 │  │ [记为灵感] [记为待办]   │  │  创建于        │
│   日历    │  └──────────────────────┘  │  2026年9月30日 │
│          │                            │  03:07        │
│          │  今天 · 4 条                │              │
│          │  ●  灵感与待办应该只解决…    │  [编辑] [删除] │
│          │  ▪  给 STM32 那块板子…      │              │
└──────────┴────────────────────────────┴──────────────┘
```

- 左栏 `200px`：品牌 + 四个入口，**灵感 / 待办带数量角标**
- 中栏：内容区最大宽度 `640px` 居中，避免超宽行导致阅读疲劳
- 右栏 `320px`：详情面板。点开一条记录**不丢失列表上下文**（手机端仍用底部抽屉）
- 桌面端不做三栏以外的额外布局炫技；数据正确优先于布局花哨

## 七、明确不改的东西

- 一级入口**仍然只有四个**：首页 / 灵感 / 待办 / 日历（顺序见 §5.8）
- 核心数据**仍然只有一种** `Record`，两种类型 `idea` / `todo`
- 首页**仍然是时间线**，不是待办列表
- 完成 ≠ 删除；删除永远是软删除且可撤销
- **不新增任何功能**（标签、分类、优先级、提醒、附件、统计、AI 等一律不做）
- `created_at` 永不改变；时间戳一律以用户写下的那一刻为准

### 9.1 第二轮迭代（用户反馈后追加）

用户提出两个问题，均已落地：

1. **「待办划去后要有一个可以被撤回的选项，有时候会不小心就把它删掉了」**
   → 见 §5.7。原实现只有一个 5 秒的 Toast 撤销入口，用户根本没赶上。
   现在待办页底部有常驻折叠的「已完成」区，任何时候都能撤销；
   Toast 也延长到 8 秒。
2. **「日历要在最下面那一个档，上面是灵感和待办」**
   → 见 §5.8。导航顺序改为 `首页 · 灵感 · 待办 · 日历`，桌面侧栏与手机底部导航一致。

新增/改动的文件：

- 新增 `src/components/CompletedTodoRow.tsx`（已完成行，含明确的「撤销」按钮）
- `src/pages/TodosPage.tsx`：底部折叠「已完成」区 + `handleUndo`
- `src/hooks/useRecords.ts`：新增 `useDoneTodos`
- `src/domain/record.ts`：新增 `byCompletedAtDesc`
- `src/utils/time.ts`：新增 `formatDoneStamp`（「今天 14:32 完成」）
- `src/app/navItems.ts`：顺序调整
- `src/app/toastStore.ts`：`TOAST_UNDO_MS = 8000` / `TOAST_NOTICE_MS = 2500`

**一处留给产品决策、本方案未擅自处理**：目前只有首页有写入入口
（`QuickCapture`）。灵感页 / 待办页 / 日历页都没有输入框 —— 这是 V1 施工方案
「唯一写入入口」的约定。但从用户习惯看，在「灵感」页想直接加一条灵感却找不到
输入框是合理的困惑点。是否需要把入口带到其他页面，需产品侧确认后再动，
因为 E2E 用严格模式断言了 `quick-capture` 的唯一性。
