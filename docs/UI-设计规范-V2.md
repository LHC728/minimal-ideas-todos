# 界面设计规范 V2

> 适用于「一刻」。本文件只定义**视觉与交互清晰度**，
> 不改变产品方向：四个一级入口、一种 `Record` 数据、首页是时间线、完成≠删除、
> 不新增任何功能。

---

## 一、设计目标

产品只解决两件事：**突然想到一个东西 → 立即记下来**；**突然想到一件要做的事 → 立即记下来并完成**。
核心体验是「想到 → 写下 → 继续做自己的事情」。

因此界面的第一职责是：**让「在哪里写」和「写了什么」永远一眼可见。**
美观是第二位的，服务于可读性，不是独立的装饰目标。

判断任何改动的标准：**它有没有让「想到 → 写下」更快？**

## 二、当前界面存在的问题（设计审计）

| # | 问题 | 证据 |
| --- | --- | --- |
| 1 | **对比度不合格** | `--color-ink-faint: #a8adb3` 在白底上仅 **2.2:1**（AA 要求正文 4.5:1、大字 3:1），却用在时间戳、日期分组、空态文案、日历星期、占位符、已完成内容上 |
| 2 | **字号阶梯失控** | `11.5 / 12.5 / 13 / 13.5 / 14 / 14.5 / 15 / 16 / 16.5` 共九级，相邻仅差 0.5px，人眼无法分辨，等于没有层级 |
| 3 | **灵感与待办无法扫视区分** | 两者只有一个小图标不同，但行为完全不同（一个只是记下，一个要去做） |
| 4 | **Toast 遮挡详情操作** | 提示条定位 `bottom-[calc(72px+safe-area)]`，正好压在底部抽屉的按钮上 |
| 5 | **空态没有指引** | 「你记下的每一条灵感与待办，都会按写下的时间留在这里」是文学描述，新手读完仍不知道下一步做什么 |

## 三、设计令牌

### 3.1 色彩

| 令牌 | 值 | 用途 | 对比度 |
| --- | --- | --- | --- |
| `canvas` | `#FAF9F7` | 页面底色（暖纸感） | — |
| `surface` | `#FFFFFF` | 卡片、面板 | — |
| `sunken` | `#F4F2EF` | 输入区底、侧栏底 | — |
| `ink` | `#1F2328` | 正文、标题 | 15.01 : 1 |
| `ink-soft` | `#5A6169` | 次要文字、**时间戳**、元信息 | 5.96 : 1 |
| `ink-faint` | `#8B9199` | 装饰性辅助（**不得承载关键信息**） | 3.02 : 1 |
| `line` | `#E9E6E1` | 分隔线、边框 | — |
| `line-soft` | `#F0EEEA` | 更轻的分隔（列表内） | — |
| `idea` | `#8F5D21` | 灵感主色（赭石） | 5.31 : 1 |
| `idea-soft` | `#F7F1E8` | 灵感浅底 | — |
| `todo` | `#4A6D8A` | 待办主色（雾蓝） | 5.19 : 1 |
| `todo-soft` | `#EAF0F5` | 待办浅底 | — |
| `project` | `#4F46A3` | 大事主色（靛紫） | 7.29 : 1 |
| `project-soft` | `#EFEDF9` | 大事浅底 | — |
| `danger` | `#B4544B` | 删除等破坏性操作、**过期的倒计时** | 4.63 : 1 |
| `on-idea` | `#FFFFFF` | 压在 `idea` 实心块上的文字 / 图标 | 5.59 : 1 |
| `on-todo` | `#FFFFFF` | 压在 `todo` 实心块上的文字 / 图标 | 5.46 : 1 |
| `on-project` | `#FFFFFF` | 压在 `project` 实心块上的文字 / 图标 | 7.67 : 1 |
| `scrim` | `rgba(28,28,30,.28)` | 弹层背后的遮罩 | — |

**为什么是三个语义色**：灵感是发散、待办是行动、大事是「在推进的长期目标」，
三者的行为都不同。赭石（暖）/ 雾蓝（冷）/ 靛紫（深冷）都是低饱和色，
在暖纸底上互不打架，但扫视时一眼能分出类型。
这是「易用」层面的改进，不是装饰。

靛紫刻意**比前两个更暗、更沉**：它是唯一一个自带「权重」的类型
（进度条、倒计时），颜色必须压得住那两条信息，不能跟灵感抢注意力。

**硬规则**：任何承载信息的文字，对比度不得低于 4.5:1。
`ink-faint` 只允许用于分隔线旁的小圆点、装饰性描边等不承载语义的位置。

**⚠️ 这些数字是脚本量出来的，不是眼睛看出来的。** `npm run check:contrast`
会从 `src/index.css` 解析**真实令牌**逐对计算，并已进 CI 门禁。上一版文档里
`idea` 写着 4.6:1，实测只有 3.11:1（白字压在赭石按钮上更是只有 3.28:1）——
十六进制字符串看不出对比度，改配色必须跑脚本。

**为什么有 `on-idea` / `on-todo`**：原先主按钮上的文字直接写 `text-white`。
浅色主题下没问题，但深色主题为了在深底上可读，`idea` 会变成**浅金**——
白字压上去立刻失效。所以「压在实心色块上的颜色」必须也是令牌，
它才反过来：浅色主题是白，深色主题是近黑。组件里不要再出现 `text-white`。

### 3.2 深色主题

深色**不是另做一套界面**，只是同一套令牌换一组值：`html.dark { --color-x: ... }`，
名字一个都不改。所有组件因此零改动 —— 这正是令牌存在的意义。

| 令牌 | 浅色 | 深色 | 深色实测对比度 |
| --- | --- | --- | --- |
| `canvas` | `#FAF9F7` | `#1A1817` | — |
| `surface` | `#FFFFFF` | `#24221E` | — |
| `sunken` | `#F4F2EF` | `#121110` | — |
| `ink` | `#1F2328` | `#F2EFE9` | 15.42 : 1 |
| `ink-soft` | `#5A6169` | `#A8A29A` | 6.99 : 1 |
| `ink-faint` | `#8B9199` | `#787168` | 3.67 : 1 |
| `line` | `#E9E6E1` | `#33302B` | — |
| `line-soft` | `#F0EEEA` | `#272420` | — |
| `idea` | `#8F5D21` | `#D2A259` | 7.63 : 1 |
| `idea-soft` | `#F7F1E8` | `#2C2318` | — |
| `todo` | `#4A6D8A` | `#8DB1CD` | 7.84 : 1 |
| `todo-soft` | `#EAF0F5` | `#1C2831` | — |
| `project` | `#4F46A3` | `#A99EE8` | 7.37 : 1 |
| `project-soft` | `#EFEDF9` | `#2A2545` | — |
| `danger` | `#B4544B` | `#DD8A80` | 6.76 : 1 |
| `on-idea` | `#FFFFFF` | `#17161A` | 7.76 : 1 |
| `on-todo` | `#FFFFFF` | `#17161A` | 7.98 : 1 |
| `on-project` | `#FFFFFF` | `#17161A` | 7.50 : 1 |
| `scrim` | `rgba(28,28,30,.28)` | `rgba(0,0,0,.62)` | — |

两条**必须保持**的关系（破坏了深色界面会「塌」）：

1. **`surface` 恒比 `canvas` 亮，`sunken` 恒比 `canvas` 暗。** 层级方向与浅色一致，
   卡片才仍然是「浮起来」的。
2. **不用纯黑。** `canvas` 取 `#1A1817`（带一点暖），保留「暖纸感」的性格；
   纯黑在 OLED 上边缘会发涩，且与暖色语义色打架。

深色下 `--shadow-*` 也整体加深（`rgba(0,0,0,.4)` / `.6`）——
浅色那套淡阴影在深底上完全看不见，抬升层级会失效。

主题有三态：`system`（默认）/ `light` / `dark`，存储键 `inspiration-todo/theme`。
「跟随系统」是默认值，因为手机上开了夜间模式而应用还是白的，那才是 bug。
实现见 `src/app/themeStore.ts`，首屏防闪脚本内联在 `index.html` 的 `<head>` 里
（必须在浏览器画出第一帧之前跑，否则深色用户每次打开都会先闪一帧白）。


### 3.3 字号阶梯（七级，相邻至少差 2px）

| 级别 | 字号 | 字重 | 用途 |
| --- | --- | --- | --- |
| display | 28 | 500 | 日期大标题（首页） |
| title | 20 | 500 | 页面标题（灵感 / 日历 / 待办） |
| lead | 17 | 400 | 详情正文 |
| body | 15 | 400 | 列表内容（最常用） |
| note | 13 | 400 | 说明、元信息 |
| caption | 12 | 400 | 时间戳、日期分组、数量 |
| micro | 11 | 400 | 日历星期、角标 |

字重只用 400 与 500 两档。**禁止出现 600 / 700。**

### 3.4 形状与间距

- 圆角三档：`8px`（行、小按钮）/ `12px`（输入框）/ `16px`（卡片、面板）
- 间距基准 `4px`；卡片内边距 `12–16px`；区块之间 `20–24px`
- 阴影只允许两处：**输入卡片**、**浮层**（抽屉 / 弹窗 / Toast）。
  两处的颜色由 `--shadow-card` / `--shadow-pop` 两个令牌给出
  （深色下自动加深），对应的工具类是 `card-raised` 与 `float-raised`。
  **不要在组件里再手写 `shadow-[...]`** —— 深色主题下那会变成一条看不见的阴影。
- 所有可点击目标触摸区域 ≥ `44×44px`

### 3.5 动效

- 打勾完成：勾选框 `200ms` 填充动画，随后该行 `420ms` 淡出上移
- 抽屉 / 弹窗：`220ms` 上滑 + 淡入
- Toast：`200ms` 淡入
- 全部动效在 `prefers-reduced-motion: reduce` 下降为 0.01ms

## 四、视觉语言：形状即类型

这是本方案的核心识别点。

| 类型 | 节点形状 | 颜色 |
| --- | --- | --- |
| 灵感 | **实心圆** | 赭石 `idea` |
| 待办（未完成） | **空心圆角方** | 雾蓝 `todo` 描边 |
| 待办（已完成） | **实心圆角方 + 勾** | 雾蓝填充（勾用 `on-todo`），内容加删除线并降为 `ink-soft` |
| 大事 | **实心横胶囊** | 靛紫 `project` |
| 进展 | **细横线**（11×2px） | 靛紫 `project` / 60% 不透明 |

**已完成的内容用 `ink-soft` + 删除线，不用 `ink-faint`。** 它是记录本身，
是信息而不是装饰；`ink-faint` 只有 3.02:1，承载内容会读不清。
「降级」靠删除线和位置表达，不靠把字压到看不见。

圆形 = 发散的想法，方形 = 待勾选的行动，**横胶囊 = 一条进度条**
（13×8px 的圆角长条，读起来就是「这事在往前走」）。
**细横线 = 大事底下的一笔流水** —— 它同色但比胶囊细得多、也短得多，
一眼能分出「这是大事本身」还是「大事的一条进展」。
**不读文字也能扫出哪条是什么。**
导航图标沿用同一套语言，保持认知一致。

四类节点都在 `src/components/RecordNode.tsx` 里统一实现 ——
新增页面时**只从这里取**，别自己画一个，否则迟早出现
「首页是胶囊、搜索里是圆点」这种同一条记录两种长相。

## 五、逐界面设计

### 5.1 首页 · 时间线

```
┌──────────────────────────────┐
│  ● 仅本机            [搜索][设置] │
│                              │
│  9月30日                      │  ← display 28
│  星期三                       │  ← caption 12
│                              │
│  ┌────────────────────────┐  │
│  │ 想到什么，先写下来        │  │  ← 输入卡片（16px 圆角 + 阴影）
│  │                        │  │
│  │ [● 记为灵感] [▪ 记为待办] │  │
│  └────────────────────────┘  │
│                              │
│  ┌────────────────────────┐  │
│  │ 目前在做的大事  3 件 ── ＋ │  │  ← 独立模块（16px 圆角 + 阴影）
│  │                        │  │
│  │  ▬ 把智能车的电源板画完   │  │  ← 横胶囊 = 大事
│  │  │  ▓▓▓▓▓▓▓░░░░░░░░  0% │  │
│  │  │  已过期 3 天 · 9月30日 │  │  ← 过期 = 红
│  │                        │  │
│  │  ▬ 写完毕业论文初稿      │  │
│  │  │  ▓▓▓▓▓▓▓▓░░░░░░░ 50% │  │
│  │  │  还剩 2 天 · 10月5日   │  │
│  └────────────────────────┘  │
│                              │
│  今天 · 4 条 ───────────────  │
│  │                           │
│  ●  灵感与待办应该只解决两件事   │  ← 实心圆 = 灵感
│  │  03:07                    │
│  │                           │
│  ▪  给 STM32 那块板子加个 CAN  │  ← 实心方+勾 = 已完成
│  │  03:07 · 已完成             │
│  │                           │
│  ●  可以试试把日志按天分文件     │
│  │  03:07                    │
│  │                           │
│  ▫  周末把智能车驱动板焊完      │  ← 空心方 = 待办
│     03:07                    │
└──────────────────────────────┘
```

要点：

1. 输入区是**整个 APP 唯一的写入入口**，必须是页面上视觉权重最高的元素：
   白底、16px 圆角、带阴影、占位文字用可读灰度。
2. 按钮文案从「灵感 / 待办」改为 **「记为灵感 / 记为待办」**，
   直接说明点击后果，消除「不知道点了会发生什么」。
3. 未输入内容时按钮**不降低透明度**（那会让按钮消失），
   而是换成中性灰描边；输入后变为各自的语义色。**形状恒定，只换颜色。**
4. 桌面端自动聚焦输入框（`pointer: fine`）；手机端不自动聚焦，避免弹出键盘遮挡。
5. 时间线左侧是一条 `1px` 的极细竖轴，节点承载类型信息。
6. 日期分组头为「今天 / 昨天 / 9月28日」+ 条数，右侧接一条渐隐分隔线。

### 5.1.1 首页 · 「目前在做的大事」模块

**它不是一个新的一级页面**，而是插在输入框与时间线之间的一栏。
理由是它和时间线回答的是两个相反的问题：

| | 回答的问题 | 排序 |
| --- | --- | --- |
| 时间线 | 我什么时候记下了什么（向后看） | 创建时间倒序 |
| 大事模块 | 我现在该先干哪个（向前看） | **截止日升序** |

要点：

1. **只列未完成的**（进度 < 100%）。推到 100% 就从这里消失 ——
   但**不会丢**，它仍然在下面的时间线里、也在日历里。
   模块是「待办视图」，不是「数据存放处」。
2. 每行三行结构：内容 / 进度条 + 百分比 / 倒计时（没设截止日就不显示第三行）。
3. 倒计时只有三档语气，**不用语义色借位**：
   平静 → `ink-soft`；三天以内 → `ink`（更实）；已过期或今天到期 → `danger`（红）。
   刻意不用 `idea`（赭石）来表示「快到了」，那是灵感的语义色。
4. **新建入口就在这个模块里**（右上角 ＋），就地展开，不跳页面。
   快车道（记为灵感 / 记为待办）**刻意保持两个按钮不变** ——
   大事要多填一个截止日，塞进快车道会拖慢最常用的那条路径。
   截止日**可以留空**：先记下来，之后在详情里补。
5. 详情面板里的编辑区（`ProjectEditor`）才有滑块和档位按钮。
   滑块**拖动时只改界面，松手才落库一次** —— 一次拖动会触发几十个
   `change` 事件，跟着写库会让首页模块重渲染几十次。
6. 时间线里大事**照常出现**，但只显示内容 + 时间，不显示进度条 ——
   时间线的职责是「我什么时候记下的」，不是「做到哪了」。
7. 写过进展的大事，在倒计时那一行右侧多一个 `N 条进展`（12px / `ink-soft`）。
   **没写过就不显示**（不写 `0 条进展`）—— 空计数是噪音。
   它是「点进详情能看到东西」的提示，不是一个要用户去凑满的指标。
   计数由 `useLogCounts` **一次遍历算全部**，不是每行挂一个 liveQuery：
   首页同时有十几件大事时，后者会变成十几次订阅。

### 5.2 灵感页

- 标题「灵感」+ 副标题「记下了 N 个想法」
- 按天分组，行结构与首页一致（但无竖轴，因为类型唯一，轴无信息量）
- 空态改为可执行指引：「还没有灵感。在首页输入框写下第一个想法吧。」

### 5.3 待办页

- 标题「待办」+ 副标题「还有 N 件没做」
- **换成行动清单的语言**：左侧 `19px` 大勾选框、行间 `0.5px` 细分隔线、去掉时间线
- 这里不需要回答「什么时候记的」，只需要回答「还有什么没做」
- 完成后该行 `420ms` 淡出并离开列表，同时弹出「已完成 / 撤销」
- 列表底部有默认折叠的**「已完成」区**，见 5.7

### 5.7 已完成区（撤销误打勾）

打勾这个动作太轻了 —— 手滑一下那条就从列表里没了，而弹窗提示只有几秒。
**只有几秒的撤销入口等于没有**，用户意识到点错的时候它已经消失了。
所以待办页底部有一块常驻的「已完成」区：

- 折叠态：`▸ 已完成 · N 条`，一行，样式与日期分组头一致，不干扰主列表
- 展开态：每条显示划线内容 + **「今天 14:32 完成」** + 一个写明「撤销」的按钮
- 时间必须带「完成」二字 —— 否则会被误读成创建时间
- 撤销按钮是**带文字的按钮**，不是图标：用户就是没看见上一次的撤销机会，
  这次不能再靠一个符号去暗示
- 撤销按钮触摸目标 ≈ `44px`（行高 `56px` 减去上下 `6px`）

**这块区不是归档，是后悔药。** 所以：
- 不做分组、不做时间窗、不分页 —— 归档归首页时间线和日历管
- 不做勾选框（勾选框在这里只会让人以为是「再勾一次」）
- 行用 `data-testid="completed-row"`，与主列表的 `record-row` 分开，
  这样「打勾后从待办列表消失」的既有约定仍然成立

同时把带撤销按钮的 Toast 默认停留时间从 `5s` 提到 **`8s`**（`TOAST_UNDO_MS`），
纯确认类提示用 `TOAST_NOTICE_MS = 2500ms`。

### 5.8 导航顺序

`首页 · 灵感 · 待办 · 日历`。

灵感与待办是「记东西 / 做事情」这一对，挨在一起；日历是「回看某一天」的检索入口，
排最后。桌面侧栏竖排时日历就在最下面，手机底部导航横排时日历在最右边，两边一致。

### 5.4 日历页

- 月份标题「2026年9月」+ 左右翻月
- 日期格：数字 + 有记录的日子下方一个 `4px` 赭石圆点
- **今天**：数字用赭石色；**选中**：`26px` 赭石实心圆 + 白字
- 下方列出该日全部记录，标题「9月30日 星期三 · 2 条」
- 日历回答的是「我在哪一天记下了什么」，**不是**「某一天要做什么」

### 5.5 详情

- 手机：底部抽屉；桌面：右侧面板（见 5.6）
- 内容用 `lead 17px`
- 元信息表：创建于 / 最后编辑（有则显示）/ 完成于（有则显示）
- 操作：编辑、删除、（已完成则）恢复为待办
- **删除永远是可撤销的软删除**，弹出「已删除 / 撤销」
- **大事的详情多两块**：上面是 `ProjectEditor`（进度条 + 截止日），
  下面是 `ProjectLogs`（见 5.5.1）。顺序不能反 —— 先看「现在到哪了」，
  再往下读「一路怎么走过来的」。

### 5.5.1 大事详情 · 进展记录

用户的原话：「我要记录每一条我做到哪里了，可以在详情里去写记录」。
所以它是一本**流水账**，不是待办清单。

```
┌──────────────────────────────────┐
│  写到哪一步了？              [记下来] │  ← 输入框 + 按钮
│  会顺手记下当前进度 40%              │  ← 12px / ink-soft，说明会带上什么
├──────────────────────────────────┤
│  今天 14:32  40% · 把绪论写完了        │  ← 最新在最上
│  昨天 22:10       · 开题报告交了       │  ← 当时没记进度，就不显示百分数
│  10月1日 09:05  15% · 文献看完一半     │
└──────────────────────────────────┘
```

- **最新在最上**（`byCreatedAtDesc`）。写流水账时刚写下的那条要立刻在眼前，
  不用往下翻。这跟时间线（首页）的方向相反，是刻意的。
- **每条顺手记下当时的进度**（用户拍板「要」）。显示成 `40% · 内容`，
  百分数在前、用 `ink-soft`，内容在后、用 `ink` ——
  扫一眼就能看出「这条之后到了多少」。
- **当时没记进度就不显示百分数**，不要补一个 `0%`：
  「没记」和「记了 0%」是两回事（`progress` 允许为 `null`，就是为这个）。
- 时刻用**相对时间**（今天 / 昨天 / 前天 / 更早则 `10月1日`），
  走 `formatRelativeStamp()`。流水账的语境是「刚才 / 前几天」，
  绝对日期反而要在脑子里做减法。**时刻只用 `ink-soft`**（`ink-faint` 3.1:1 不够）。
- **点一下某条即可就地编辑**（内容 + 删除），删除给常驻撤销路径。
  流水账写错字是常事，不该逼用户先删再重写一遍。
- 空态一句话就够：`还没有进展`。不要插图、不要引导文案。
- **不给进展打勾、不做子任务、不做提醒**（见 §7）。

这条流水**不进首页时间线、不进日历、不进搜索**。它属于那件大事，
答案在详情里；把它摊进时间线会淹没「我什么时候记下了什么」这条主线。

### 9.4 第五轮迭代：进展（大事详情里的逐条记录）

用户提出：「我需要的进度记录不只是这么简单，这个可以保留，但我还要去记录
我到哪一步了。具体来说，我要记录每一条我做到哪里了，可以在详情里去写记录。」
已落地，见 §4（形状）、§5.5.1（进展记录区块）、§5.1.1 第 7 条（`N 条进展`）。

两个由用户当场拍板的选择：

1. **进展不进首页时间线**（推荐项）。时间线回答「我什么时候记下了什么」，
   进展是某件大事的内部流水，摊进去会把主线淹掉。
2. **每条顺手记下当时的进度**（推荐项）。于是 `40% · 把绪论写完了` 成为常态 ——
   这条流水本身就成了一条「进度曲线」。

**最关键的一个决定：进展复用 `Record`，不新开一张表。**

| | 复用 Record | 新开一张 logs 表 |
| --- | --- | --- |
| 新增的代码 | 几个字段 + 过滤器 | outbox / 推送 / 拉取 / 三方合并 / 软删除 / 撤销**各抄一遍** |
| 新增的丢数据点 | 0 | 5 处（每一份新代码都是一个） |
| 代价 | idea / todo 上多几个恒为 null 的字段 | —— |

整个 APP 只有一种核心数据，这条底线比「表结构好看」重要得多。
代价是过滤器必须**显式**排除 `log`（首页 / 日历 / 搜索三处），
好在都收在 `domain/record.ts` 一处。

三条实测出来的坑：

1. **`parentId` 必须是不可变字段**。进展属于哪件大事是写下来那刻定死的。
   数据库层钉进 `records_created_fields_immutable` 触发器；服务端的 update
   路径**根本不 SET 它**；`ConflictService` 里它跟随 base 且**不进 `MergeField`** ——
   放进去会让用户在冲突弹窗里面对一个他无从判断的选项。
2. **「没记进度」和「记了 0%」不是一回事**。`progress` 对进展允许为 `null`，
   而 Worker 的更新路径用「**键在不在**」判断（`has(payload, 'progress')`），
   所以清空必须传**显式 null**，传 `undefined`（键不存在）会被当成「没打算改」。
3. **`parentId` 的空白串必须归一成 `null`**。空串既不等于 `null`、又匹配不到
   任何大事 id，会让那条进展在所有设备上「挂在一个不存在的大事下」——
   界面表现是**凭空消失**。`clampParentId` / `asParentId` 两处都挡了它。

还有两处只有真跑起来才会发现的：

- **Dexie 必须升到 v3**。老记录的 `parentId` 是 `undefined`，云端返回 `null`，
  `snapshotEquals` 用严格相等 —— `undefined ≠ null` 会凭空造出「删除冲突」弹窗。
  （和上一轮 `progress` 的坑是同一个坑，只是换了个字段。）
- **D1 迁移 0003 不能照抄 0002 的「搬数据」那一段**。0002 时 `progress` 是
  刚加的新列，只能写 `select null`；到 0003，线上已经有大事带着**真实进度**了，
  照抄就会把用户攒的进度**全部清零且不报错**。必须逐列原样搬。
  这条已由 `src/test/d1Migration.test.ts` 与 `scripts/verify-d1-migration.mjs`
  两份实现分别钉住。
